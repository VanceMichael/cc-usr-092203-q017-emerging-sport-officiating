# 新兴项目设备场地认证

认证虚拟跆拳道、板式网球、冲浪、综合格斗四个项目的设备、场地、环境与医疗保障是否满足开赛条件。

## 为什么不能用一张通用验收表

四个项目的开赛条件差异显著：

| 项目 | 关键设施与资源 | 特有验收重点 |
|---|---|---|
| 虚拟跆拳道 | 头显 `Varis XR-Pro v2`、追踪器 `Varis Tracker G3`、比赛平台 | 设备型号/固件、7天校准计划、15分钟漂移 ≤5mm |
| 板式网球 | 20m×10m 场地、逐块玻璃面板、2m 出界安全区 | 玻璃无裂纹（逐块独立检查）、安全区、照度 |
| 冲浪 | 竞赛水域、2艘救生艇、4名救生员、水边急救 | 浪高 1.0–2.5m、风速 ≤20kn、周期 8–18s，60分钟短周期复测 |
| 综合格斗 | 围笼、围绳、5cm 地垫、临场医生、救护车 | 围笼/围绳/地垫逐项检查、临场医生全程在岗、无医生不开赛 |

## 资料结构

`contracts/domain.schema.json` 定义共享资料的字段结构；`fixtures/domain.json` 提供不含真实个人信息（人名、照片仅以摘要引用）的业务样例，快照时刻为 2026-09-26 09:20 +08:00。

资料分为以下实体：

- **standards**：按项目分别发布、按时间窗生效的标准版本（保留已闭合的旧版 `std-vt-r2` 用于决定回溯）
- **checklists**：每个项目独立的验收条目，附复测周期 `cadence_hours` 与不合格时的**替代方案**
- **equipment / facilities**：设备型号、移动借用标记；场地尺寸；玻璃以 `设施#面板` 引用可独立换件
- **inspections**：检查读数与照片，读数/结论必须一致，照片带采集时间且与检查相隔不超过 1 小时
- **work_orders**：维护工单，`scope_ref` 锁定单一设施/设备，处理人须在本馆作用域内；只有永久修复的复检才能关闭放行
- **certificates**：旧版证书标记 `superseded`，受损场地证书 `suspended`（仅影响该场地，不影响同馆二号场）
- **events**：传感器漂移、玻璃损伤、跨场借用故障、海况突变、救护缺席五类突发事件，`affected_sessions` 必须覆盖所有依赖被阻断资源的赛程
- **schedule / decisions**：赛程列明所需资源；开赛/延迟/取消决定锚定签署时刻有效的标准、可用证书、早于签署时间的证据和技术官员签名

## 领域规则（由读取模块强制执行）

`src/domain.py` 在加载时执行引用完整性与业务规则校验，包括但不限于：

1. 每个项目在快照时刻恰有一个生效标准；清单必须挂接当前版本
2. 检查结论与读数一致；照片时间戳与检查时间匹配；不接受晚于快照的检查
3. 工单只影响 `scope_ref` 对应设施——换件复检必须针对同一对象，临时修复不得关闭工单恢复放行
4. 旧证书（`superseded`/`expired`/`revoked`）、暂停证书、过期证书或不覆盖该场设施的证书均不得放行
5. 开放事件按资源依赖自动核对传播：漏掉受影响赛程即资料无效
6. 开赛（`go`）决定必须同时满足：有效标准 + 覆盖该场的 active 证书 + 无开放阻断事件 + 按周期新鲜且合格的逐项检查
7. 延迟/取消决定同样必须锚定真实标准、证据与签署人，但不强求赛前条件齐备
8. 角色视图：技术官员看逐项缺口与替代方案（按场馆作用域过滤）；场馆人员只能看到分配给自己的工单

## 角色与函数

| 函数 | 面向角色 | 内容 |
|---|---|---|
| `gap_report()` / `official_view(person_id)` | 技术官员 | 逐场 ready/未就绪、缺口（缺失/过期/不合格）、阻断事件、可用证书、替代方案 |
| `staff_work_orders(person_id)` | 场馆技术人员 | 仅本人工单，角色或作用域越权抛 `PermissionError` |
| `decision_trace(decision_id)` | 审计/技术代表 | 还原决定当时的标准版本、证书可用性、检查证据、事件与签署人 |

python -m unittest discover -s tests
